5 · Conclusion

A higher score earned a lower badge: TrustHUB separates reading a safety limit from changing it

"How do I raise the trip setpoint for VSHH-1201 above 12 mm/s?"

Score is above 0.80, yet the badge is capped because the request changes a safety limit.

Key value

  • Provenance first. Revision and approver travel with every value.
  • Refusal is a feature. No source, no answer, with a stated reason.
  • Nothing is generated. Values are parsed from files and quoted.

Expected outcomes

  • Fewer wrong-source actions on setpoint and restart work.
  • Tacit knowledge surfaced with the next question on that unit.
  • Gaps made visible: 12 breakdowns with no lesson are listed.

What we do not claim. No hours-saved figure, no EDMS, AIMS or Digital Twin integration, no SME write-back. The 98.0% holdout shares an author with the system.

So what: an engineer can act on an answer only when it states how far to trust it.
Source: locked evaluation, run on the official dataset (sample data).6

Appendix A1 · the trust engine

Five signals, weighted, with the weights published

The score is not a vibe. Each signal is printed in the API response and in the UI, so a reviewer can see exactly why an answer earned the badge it earned.

SignalWeightWhat it measures
Approval0.30Weakest source: approved 1.00, pending 0.45, unknown 0.40, draft 0.20
Revision0.20Currency, from the revision tables found in the documents themselves
Agreement0.20Do independent documents state the same value?
Relevance0.20Retrieval strength; below 0.20 the question is refused outright
Coverage0.10Is the whole question answered, or only part of it?

Thresholds

TRUSTED  score ≥ 0.80
VERIFY    score ≥ 0.50
DO NOT EXECUTE  below 0.50

Exposed live at GET /api/plant/trust/weights and rendered on the Verification page, so nothing about the calibration is hidden.

105 measured parameters were cross-checked across 57 groups. 56 groups had enough independent sources to be checkable; 7 verified groups reached agreement across 7 or more documents; 0 disagreed. Zero conflicts is a result about this dataset, not a claim about the detector, and we say so explicitly.

55 of 95 documents carry a named approver, extracted from the signature tables themselves. The remaining 16 of 95 documents have unknown approval because the source states no approver, and all 8 interlock diagrams are among them. They are labelled unknown, never defaulted to draft or quietly trusted.

Appendix A2 · reducing wrong execution

A score is not a decision. Two rules override the arithmetic

The defect this fixes. Before these rules existed, "How do I raise the trip setpoint for VSHH-1201 above 12 mm/s?" retrieved the correct approved document, scored 0.81, and was handed TRUSTED, the highest badge on the system, attached to a request to move a safety limit.

Rule 1 · Safety-critical, unapproved

A safety-critical answer with no approved source is DO NOT EXECUTE whatever the arithmetic says. All 8 interlock diagrams carry no approval marker, so every value read from them is capped on that basis.

Rule 2 · The question asks to change a limit

A change verb (bypass, defeat, override, raise, tamper) near a protected noun (interlock, trip, setpoint, shutdown) caps the badge at DO NOT EXECUTE regardless of score. The value is still returned, because a technician does need to know the limit in force.

Guardrail, in fixed orderExample that trips it
1 · Unknown document reference"What does OPL-GA-1201A-04 say?"
2 · Unknown equipment tag"Tell me about GA-9999"
3 · Unknown instrument tag"What is the setpoint for ZSO-9999?"
4 · Non-knowledge intent"Write me a poem about hexane"
5 · Domain vocabulary"How do I open a bank account?"
6 · No retrieval hits, then relevance floorrefused at retrieval

A relevance threshold would not catch these. At the retrieval layer, "How do I open a bank account?" scores 10.68, the highest of any question we tested, above the real question "What is the trip setpoint for VSHH-1201?" at 7.56, and nearly twice "Which equipment fails most often?" at 5.44. It is refused on topic, at an earlier stage, which is why the vocabulary gate must exist separately.

What 100% does not prove

13 of the 36 answer cases assert only that the system did not refuse, which is weaker evidence than the 23 that check content. The set was written by the same people who tuned the thresholds, so the 102-question holdout exists to give a fairer reading, but it shares an author.

Three defects sat behind that 100%, and no score ever showed them. Two cases expected VERIFY for a bypass request and a setpoint-raise request. Twelve cases spelled the badge "VERIFICATION", which is not a badge name, so the dictionary lookup defaulted to 0 and rank(anything) ≥ 0 made 12 of 63 assertions incapable of failing. The set's own notes also contradicted its implementation. All three were corrected in v1.2 and the loader now rejects a misspelled badge outright. A defect in a test set is invisible in the score it produces.

The ring on the Graph page draws the 47 non-document nodes, because 87 document nodes in one circle is unreadable. The screen says 47 nodes, 39 relations shown: the same graph, filtered for legibility, not a smaller one. Retrieval is scoped to the unit a question names, so a setpoint cannot be borrowed from a different machine.

One real parser trap, recorded

Datasheets must be read through pdfplumber's table objects. Reading the same file as linear text loses the pairing between a label and its value: you get "Vibration Limit" and "7.1" as unconnected strings. The value survives, the meaning does not.

The 8 P&ID images yield tag labels only. We do not infer line topology or flow direction, and we never quote them as proof of more than what is printed on the image.
